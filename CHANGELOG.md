# Changelog

All notable changes to btc-toolkit. Format based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/);
versioning follows [SemVer](https://semver.org/). The `--json` output follows the stability policy in
[`docs/json-schema.md`](https://github.com/devdavidejesus/btc-toolkit/blob/main/docs/json-schema.md).

## [Unreleased]

## [1.8.2] — 2026-10-22

Fixes found by running every command and every shell completion by hand on macOS, and by an independent audit of
`verify` and the parsers. The `--json` output keeps its keys and their meaning.

### Added
- Static fish shell completion (`completions/btc-toolkit.fish`) alongside bash and zsh, contributed by @montionugera
  (#69).
- `btc_toolkit.api.BadRequestError`, a `MempoolAPIError` for HTTP 400.
- A test that presses Tab in a real zsh, bash and fish, for commands, options after the command and after an operand,
  and `-n` network values.
- `.github/FUNDING.yml`: GitHub's Sponsor button links to the README's on-chain Support section.
- `CODE_OF_CONDUCT.md` (Contributor Covenant 3.0), issue forms for bug reports and feature requests (security
  reports go to private reporting), and a pull request template.
- Python 3.15 in the CI test matrix and the package classifiers.

### Fixed
- zsh completion (#58): Tab completed the command names but none of their options or values (`tx --in`, `block 0 -n s`
  completed nothing). It now completes every option and the `-n` networks, after the subcommand and after the
  txid, address or block.
- `verify`: the Merkle proof of a block's last transaction also hashed to the root at positions past it, where Bitcoin
  pairs a duplicated node. Those positions are now refused, so the reported `position` is always a real
  transaction's. The verdict itself was not affected: the transaction was in the block.
- `utxo` on an address with tens of thousands of UTXOs, which the API refuses with HTTP 400, now says so and points
  to `balance` instead of a bare "API error 400: Bad Request".
- `block` showed a difficulty below 1 (signet, regtest) as `0`; it now shows it with four significant digits, as
  `verify` does.
- With `--api-url` or `$BTC_TOOLKIT_API_URL`, the line under the banner says "custom API" instead of
  "Mempool.space API".
- Text output also escapes the Unicode line and paragraph separators (U+2028, U+2029) in on-chain text and echoed
  input, like other control characters.
- The sdist ships `completions/`: in 1.8.1, the test suite failed 4 completion tests when run from the sdist.

### Changed
- The fuzzer now also covers `verify` and the address overview: `verify_tx` is fed arbitrary API answers and,
  half of the time, answers that agree with each other, so every check up to proof of work is reached.
- Docs: the exit-code note says which commands return `1` for an unconfirmed transaction (only `verify`), and
  `SECURITY.md` says that the repository's only lockfiles pin CI tools.
- Docs: `SECURITY.md` and `docs/releases.md` say that release tags are signed with the maintainer's SSH key
  from 1.5.0 on, and how to verify one.
- Docs: the 50 T threshold behind `"work": "strong"` is btc-toolkit's own, not a consensus rule, and a script
  that must reject forged proofs should check `work`, not only `verified`.
- README: a shorter entry page, with a new "What it verifies, and what it doesn't" table, command by command. The
  full command reference moved to `docs/commands.md`, and the project layout and testing notes to `CONTRIBUTING.md`.
  It also lists btc-toolkit on bitcoin.org's Development page, and no longer lists fish (#62) or zsh (#58)
  completion as next.

### Security
- Release pipeline: signing now uses sigstore 4.5.1 with certifi 2026.10.19, and publishing uses
  pypa/gh-action-pypi-publish v1.14.3. Both drop the emSign ECC Root CA - G3 after the eMudhra CA incident
  of October 2026. The package itself never bundled certificates: it uses Python's default TLS context, and so
  the system's certificates.

## [1.8.1] — 2026-10-15

A new look, and a PyPI page that describes 1.8.0. The commands and the `--json` output are the same as in 1.8.0.

### Changed
- New visual identity, built on the Bitcoin logo and its orange (`#F7931A`): `assets/icon.svg`, a README header
  for GitHub's light and dark themes (`assets/logo.svg`, `assets/logo-dark.svg`) and the social preview. They are
  generated by `.github/scripts/make_brand.py` from pinned, hash-checked fonts (JetBrains Mono, IBM Plex Sans;
  SIL Open Font License), so the images can be rebuilt and reviewed from code.
- The banner at the top of the text output is Bitcoin orange (256-colour palette) instead of cyan. `NO_COLOR` and
  piped output still print it without colour.
- The PyPI summary and the README's opening lines describe what the tool does since 1.8.0: read and verify Bitcoin
  from the terminal (OP_RETURN, inscriptions, raw transactions, offline address checks, Merkle-proof verify).
- README: btc-toolkit's listing among the developer tools in Jameson Lopp's Bitcoin resources.

## [1.8.0] — 2026-10-15

Four new commands (`verify`, `decode`, `validate`, `inscription`), `tx --inputs/--outputs`, and fixes from two
independent audits. No command or option is removed and the `--json` output only gains keys; the changes in
behavior are listed under Changed.

### Added
- `verify <txid>`: checks a transaction is in a block by computation instead of trusting the API's "confirmed". It
  recomputes the txid from the raw transaction, the Merkle root from the proof (refusing any pair of nodes that is
  also a valid 64-byte transaction, CVE-2017-12842), the block hash from the 80-byte header that must contain that
  root, and the header's proof of work. The verdict depends only on the work proven: "strong" (`✓ VERIFIED`) for a
  mainnet header at difficulty 50 T or more, about 2^77.5 hashes to forge; "weak" otherwise (older blocks, testnet,
  signet, an unknown chain), where the data is consistent but cheap to fake. It does not prove the block height or
  that the block is in the chain everyone follows; only a full node does.
- `decode <rawtx>`: decodes a raw transaction offline — legacy or SegWit — with txid, wtxid, size, weight, vsize,
  every input, witness and output (address and script type). `decode --txid <txid>` fetches the raw transaction and
  checks that it hashes to that txid.
- `validate <address>`: checks an address offline — Base58Check, bech32 (BIP 173) or bech32m (BIP 350) checksum,
  network and type — against the BIPs' official test vectors. Nothing is sent.
- `inscription <txid>`: finds Ordinals inscription envelopes in a transaction's Taproot inputs and shows each one's
  ID, content type, encoding, metaprotocol, parents, delegate, pointer, body size and SHA-256, and the text of a text
  inscription, following ord's own parsing rules. Envelope detection, not the ord index: no inscription numbers, sats
  or owners.
- `tx --inputs` and `tx --outputs`: every input (the output it spends, its value and address) and every output (its
  address, and whether it is spent and by which transaction). Addresses are computed locally from each script.
- `opreturn` names known protocol markers, by prefix, in a new `protocol` key: `runes` (a Runestone), `omni`, and
  `witness_commitment` (BIP 141, in a coinbase). They are tagged, not decoded.
- `-n` now works together with `--api-url`, to say which chain your own instance serves (before, `--api-url` always
  meant an unknown, `custom` chain). Results never link to mempool.space when you use your own instance. `validate`,
  and `decode` without `--txid`, ignore `$BTC_TOOLKIT_API_URL`: they are offline.
- Address types now include P2A (pay-to-anchor) and future witness versions (`witness_vN`).
- The fuzzer covers every new parser (raw transactions, addresses, scripts, inscription envelopes, block headers,
  Merkle proofs), and the weekly live test checks `verify`, `decode`, `validate`, `inscription` and `tx --outputs`
  against real transactions.

### Changed
- `balance`, `address` and `utxo` validate the address offline, checksum included, before any request: a typo or
  an address from another network is invalid input (exit code 2) and is never sent to the API. It used to reach the
  API and come back as an HTTP 400 (exit code 1).
- `address` reports the type decoded from the address itself.

### Security
- Text mode escapes control characters everywhere, not only in on-chain text: error messages (which can carry text
  from the API, such as an HTTP status reason), and input echoed back (a txid, address or block reference, possibly
  read from a `--file` someone else wrote). Block hashes, previous-block hashes, merkle roots and UTXO txids from the
  API must be 64 hex digits; anything else is an API error (exit code 1). JSON output was already escaped.

### Fixed
- A malformed `--api-url` or `$BTC_TOOLKIT_API_URL` (no `http://` or `https://`, no host, a bad port, spaces,
  non-ASCII characters, a user name or password, a query or a fragment) is now invalid input, exit code 2, with a clear
  message, before any request. A URL without a scheme used to end in a traceback; the others were retried and
  reported as connection errors.
- A response is read with limits: at most 32 MB, and within about twice the timeout. A server sending one byte at a
  time could otherwise keep the tool waiting forever.
- `tx` and the other transaction commands check that the API's answer is about the txid asked for.
- A lone surrogate in input (an undecodable byte) is escaped like any control character, instead of a traceback on a
  strict UTF-8 terminal.
- A JSON response nested too deeply to parse is an API error (exit code 1) instead of a traceback.
- `tx` no longer flags a coinbase transaction as RBF: a coinbase input cannot be replaced, whatever its sequence.
- An address with non-ASCII letters is rejected locally (exit code 2) with the usual message, instead of an
  encoding error.
- `opreturn --json` reports the txid normalized (lowercase, trimmed) at the top level and in `outputs[].txid`; both
  used to echo the input as typed.
- Documentation: the JSON error keys per command, how amounts and rates are typed, what `--limit` and
  `--confirmed-only` do to `utxo` output, and that only lines starting with `#` are comments in a `--file`.
- README: a quick start, with the rule that options go after the command (`btc-toolkit fees --network signet`), and
  how to install and run with [uv](https://docs.astral.sh/uv/) (`uvx btc-toolkit`, `uv tool install btc-toolkit`).

## [1.7.2] — 2026-10-10

A documentation release: the code is the same as in 1.7.1. It republishes the README on PyPI with the
corrections below.

### Added
- Homebrew install on macOS and Linux: `brew install devdavidejesus/tap/btc-toolkit`. The formula, in
  [devdavidejesus/homebrew-tap](https://github.com/devdavidejesus/homebrew-tap), installs the PyPI sdist pinned by
  its SHA-256, plus the bash and zsh completions. `docs/releases.md` describes how the formula is updated after
  each release.

### Fixed
- README and documentation claims that did not match the code: `--api-url` points to a self-hosted Mempool
  instance, not to a node; retries happen on HTTP 429, 500, 502, 503 and 504 only; `--timeout` applies to each
  network operation of each attempt; a new command also needs shell completions and tests; `tx` shows input and
  output totals; `$BTC_TOOLKIT_NETWORK` is ignored when an API URL is set. SECURITY.md now mentions the Sigstore
  bundles on GitHub Releases, and the CI lists in CONTRIBUTING.md and `docs/releases.md` include coverage,
  type-checking and the fuzzer.

## [1.7.1] — 2026-10-08

Fixes from a full audit of the code, the documentation and the release pipeline.

### Security
- On-chain text is printed with control characters escaped. Anyone can write an OP_RETURN: a message carrying
  ANSI/OSC escape sequences could rewrite the terminal screen or window title, and bidirectional-text controls could
  reorder what is shown. JSON output was already escaped.
- The release build no longer installs an unpinned setuptools: the build backend is pinned by hash, like the build
  tool, and the package is built with `--no-isolation`.
- A tag is only published if it points to a commit on `main`. Runs for the same tag never overlap, and a duplicate run
  publishes nothing: on v1.7.0 one tag push started three release runs; the first published and the duplicates failed
  at the PyPI upload.

### Fixed
- A malformed API response no longer crashes with a traceback. Every field the parsers read is type-checked, so a
  wrong type or an out-of-range value anywhere (null, a string for a number, a list of strings for a list of objects,
  a number too large for 64 bits) is a clean API error, exit code 1, and one bad response no longer aborts a batch.
  The fuzzer now covers every API parser and the values derived from it, not only the OP_RETURN decoder.
- An OP_RETURN output without data (a bare OP_RETURN, OP_RETURN OP_0, a Runestone marker with nothing after it) was
  skipped, so the command reported "No OP_RETURN outputs" and `op_return_count: 0`. It is now listed with an empty
  payload. The raw-script fallback also reads OP_PUSHDATA4 and skips OP_0 and the small-number opcodes, and a
  non-standard script keeps its bytes: a push that runs past the end returns the bytes that are there.
- `opreturn --raw` printed the banner, header and link around the hex. It now prints only the payload hex, one line
  per OP_RETURN output, with errors on stderr.
- `$BTC_TOOLKIT_API_URL` overrode an explicit `--network`; flags now always win. An unsupported
  `$BTC_TOOLKIT_NETWORK` (e.g. `testnet4`) silently fell back to mainnet; when it is used (no API URL set), it is now
  an error, exit code 2.
- Address types on signet were always `unknown`, and with `--api-url` only mainnet prefixes were recognised. Signet
  uses testnet's prefixes, and a custom API accepts every network's, including regtest's `bcrt1`. A `bc1p…` address
  of the wrong length was labelled P2TR; Taproot now requires a 32-byte key.
- `block latest` reported a non-numeric answer from the API (e.g. an HTML error page) as invalid user input, exit
  code 2; it is an API error, exit code 1. A 64-character block hash made only of digits was treated as a height.
- `--timeout nan`, `--timeout inf` and very large timeouts were accepted and then crashed; the timeout must be more
  than 0 and at most one day (86,400 s).
- `fees`: the mempool's total fee is sent as BTC × 1e8 and could arrive as 28999999.999999996; it is rounded, not cut
  down to 28,999,999 sats.
- `--file` with a byte-order mark (Windows Notepad) failed on the first item.
- `utxo --limit` accepted 0 and negative values; it must be at least 1.
- Text-mode links always pointed to mainnet's mempool.space; they now follow `--network`, and are omitted for a
  custom API.
- The shell completions offered the same flags for every command: `--raw`, `--confirmed-only` and `--limit` were
  missing, and `--file` was offered for `fees`, which rejects it. Each command now gets exactly the flags it accepts,
  and a test keeps the completions in sync with the CLI.
- The release notes check rejects an empty CHANGELOG entry, and the oldest entry no longer runs into the link list.
- The sdist ships `tests/__init__.py`, so the documented test command works from an unpacked sdist.
- Documentation: the README architecture tree and `balance` description, the exit-code reference (which errors are
  plain text), the input-validation and transport wording in SECURITY.md, `detect_address_type`'s `unknown` result,
  and outdated docstrings.

### Changed
- Refreshed the hash-pinned CI tool requirements (transitive dependencies only; the pinned tools are unchanged).

## [1.7.0] — 2026-10-07

### Removed
- Python 3.10, which reached end of life on 2026-10-01, following the documented support policy. btc-toolkit now
  requires Python 3.11 or newer. 1.6.2 keeps working on 3.10, and `pip` on 3.10 keeps installing it.

### Added
- CI measures line and branch coverage on every pull request (coverage.py, pinned by hash) and fails below 90%.
- Tests for the OP_RETURN parser edge cases that coverage showed untested, including `OP_PUSHDATA2` — the path
  that decodes messages larger than 255 bytes. `opreturn.py` coverage went from 83% to 99%.

## [1.6.2] — 2026-09-27

### Fixed
- Low-level network failures were not retried: the server closing the connection without a response
  (`RemoteDisconnected`), a read timeout or a truncated body escaped the retry logic, crashed with a traceback
  and, in batch mode, aborted the whole batch. Found decoding a real 1,170-transaction batch. They are now
  retried with backoff like any transient failure, and a batch always processes every item.
- A response that is not valid JSON or UTF-8 (for example an HTML error page) raised `ValueError`, which the
  CLI reports as invalid user input (exit code 2). It is now an API error (exit code 1).

## [1.6.1] — 2026-09-27

### Fixed
- A malformed OP_RETURN script in an API response was reported as *invalid input* (exit code 2), blaming the
  user for bad upstream data. It is now a clean API error (exit code 1). Found by the new fuzzer.

### Added
- Coverage-guided fuzzing ([Atheris](https://github.com/google/atheris)) of every parser of untrusted data, on each
  push and pull request and weekly: `fuzz/fuzz_parsers.py`.
- GitHub Releases are created by the release workflow, with the files signed by Sigstore (keyless, using the
  workflow's identity) and the notes taken from this changelog. A tag without a changelog entry cannot be published.
- A documented policy for supported Python versions: each is dropped in the first minor release after its end of life.
- CodeQL static analysis (SAST) of the Python package and of the GitHub Actions workflows, on every push and pull request.

### Changed
- CI runs the test suite with the standard library's `unittest`, straight from the source tree: no package
  and no test runner are installed. `pytest` still works for contributors who prefer it.
- The CI tools that are still installed (`build`, `ruff`, `mypy`) are pinned by hash in `.github/requirements/`
  and installed with `--require-hashes`: a tampered package on PyPI fails the build instead of running in it.
- `CONTRIBUTING.md` documents the contribution process and requirements, including tests with every change.
- `SECURITY.md` links the private vulnerability reporting form directly and commits to a 14-day initial response.

## [1.6.0] — 2026-09-27 — Typed

### Added
- The package ships `py.typed`: projects using btc-toolkit as a library get real types in their type checker.
  The whole package passes `mypy --strict`, enforced in CI.
- `docs/python-api.md`: functions, result types and error hierarchy of the Python API.
- OpenSSF Scorecard: an independent, signed supply-chain assessment, published weekly, with a README badge.
- Private vulnerability reporting enabled on the repository (referenced by `SECURITY.md`).

### Fixed
- An unexpected JSON shape from the API (upstream drift) now raises a clean `MempoolAPIError` — exit code 1 with a
  readable message — instead of crashing with an `AttributeError` traceback.

## [1.5.0] — 2026-09-26 — Provenance

### Added
- Releases are published by GitHub Actions through **PyPI Trusted Publishing** — no API token exists anymore —
  with **PEP 740 attestations**: signed provenance linking every file on PyPI to this repository and workflow run.
- `NO_COLOR` support ([no-color.org](https://no-color.org)).
- Weekly live smoke test against mainnet: reads known on-chain facts to catch upstream API drift that mocked
  tests cannot see.
- CI: Python 3.14; macOS and Windows jobs; the built wheel is installed and tested as users get it; zero
  dependencies enforced on the wheel metadata; ruff lint.
- `CHANGELOG.md`; Changelog and Security links on PyPI.

### Changed
- Packaging uses PEP 639 SPDX license metadata (the deprecated form stops building in 2027).
- GitHub Actions pinned by commit SHA, kept current by Dependabot.
- Test coverage of the CLI layer from 62% to 92% (144 tests).

## [1.4.0] — 2026-09-10 — Automation & Trust

### Added
- Environment variables `BTC_TOOLKIT_API_URL`, `BTC_TOOLKIT_NETWORK`, `BTC_TOOLKIT_TIMEOUT` (flags always win).
- `--timeout`.
- Batch mode: stdin (`-`) and `--file` on tx, opreturn, balance, address, utxo, block; `--json` emits JSON Lines.
- `SECURITY.md` (threat model), `docs/json-schema.md` (stability policy), `docs/releases.md`.

### Fixed
- `--json` mode now exits 2 on invalid input in every command, matching text mode.
